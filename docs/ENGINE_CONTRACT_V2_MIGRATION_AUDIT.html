Engine Contract v2 replaced
the legacy engine boundary.
No shims were kept.

The desktop/native path now runs through an Effect-native HTTP/OpenAPI contract. TypeScript defines the contract, OpenAPI carries it across languages, Rust and Swift consume generated protocol helpers, and the desktop host calls domain services instead of raw transport details.

This page mirrors the structure of the Bun unsafe audit: a counted breakdown, subsystem territory map, origin→pattern→outcome flow, expandable ledger, evidence passes, and a remaining-plan section. Counts are weighted implementation units from the migration plan and PR scope, not source-line counts.

  • 01Eight migration phases are complete. Contract creation, generation, TypeScript client, native bindings, native HTTP servers, desktop integration, removal, and final gates are all marked complete.
  • 02The legacy boundary was deleted, not wrapped. The old consolidated engine package, line/RPC protocol pieces, endpoint inventory, stale native streams, and project-package hook were removed rather than hidden behind compatibility layers.
  • 03Observability became part of the boundary. BunRuntime, platform-bun services, structured logs, log spans, tracing spans, metrics, process diagnostics, and optional DevTools now cover the critical desktop path.

Where the migration came from

Every implemented unit by root cause. Contract drift and native interoperability drove most of the work; desktop packaging and observability were hardening discovered during final gates.
